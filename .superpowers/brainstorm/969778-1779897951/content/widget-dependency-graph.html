Key Reuse Relationships

ui_customers reuses ui_profile
ProfileCard → customer header display
ContactListTile → customer list items
AddressTile → customer locations
ProfileSearchSelect → customer picker
ProfileBadgeById → assigned salesperson
ui_recipes reuses ui_inventory
InventoryItemPicker → BOM material selection
StockLevelCard → material availability
UnitSelector → unit-of-measure picker
ui_orders reuses ui_catalog + ui_customers
ProductGrid → product selection in cart
VariantSelector → variant picking
CustomerSearchSelect → buyer selection
BalanceCard → credit limit check
ui_production reuses ui_recipes + ui_inventory
RecipeCard → recipe selection in plan
RecipeStepList → batch step guidance
StockLevelCard → material validation
ExpiryWarningCard → output shelf life

Build Order (respecting dependencies)

Implementation phases
Phase A — Foundation (no cross-package deps):
  ui_inventory · ui_catalog · ui_equipment · ui_coldchain · ui_costing

Phase B — Tier 2 (depends on Phase A + ui_profile):
  ui_customers · ui_recipes · ui_quality · ui_waste · ui_shelflife

Phase C — Tier 3 (depends on Phase B):
  ui_production · ui_orders · ui_procurement · ui_pricing · ui_demand · ui_traceability

Each phase can be built in parallel within itself.
Dart SDK generation (proto → dart) is a prerequisite for all packages.
